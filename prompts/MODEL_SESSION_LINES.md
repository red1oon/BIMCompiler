# ⚠ DO NOT REMOVE — MODEL SESSION LINES (`model.*`): a Modeller kept open between door lines. READ THE LOG after every run (W-MODEL-SESSION).
Written 2026-11-14 (owner: "model.open (2D) /shed/ . model.2d.convert .. model.addbay <which end>", "yes 1 [open the 2D sheets] … 2. You decide. 3. You decide too"). Film use: prompts/FILM_COMMAND_LINE_ERP.md CH 1.

**What it is.** `modeller/tools/model_session.js` starts ONE headless Modeller page on the CPU (no GPU; `--use-angle=swiftshader`), a local port on 127.0.0.1 with a one-time token and a state file `.model_session.json` in the folder the door line runs from. Each door line is its own process that sends one command to that page, so `model.open`, `model.convert`, `model.addbay` act on what the line before left. The page does all the work with its own functions (the DXF import, Convert, Add a bay: `dxf_import_ui.js`, `bay_add.js`, §D89/§D90); the driver presses what a person presses and reads the page's own answers. Nothing is saved: `model.close` drops the model.
**The lines (harm `trial`, human + ai):** `model.open sheets=<folder|a.dxf,b.dxf> [type="Farming Shed"]` · `model.convert` · `model.addbay end=high|low` · `model.undo` · `model.close`. Owner's name `model.2d.convert` became **`model.convert`**: the door grammar is `app.verb` (one dot; `dotted.js`/`parseLine`); the 2D origin is implied by `model.open sheets=`. An alias with a second dot is a grammar change, not done.
