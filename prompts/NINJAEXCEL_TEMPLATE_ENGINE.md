## §TB-DEMO — public Thai trial-balance demo template (2026-10-13, user directive)
**Decision (user):** no customer template (MOES/Laos) in any film, manual or repo. The film + manual use our OWN template over GardenWorld data that is "understandable as GardenWorld" and solves a real reporting challenge.
**Challenge:** per account, for a date range: *opening* (everything before `#1`), *debit / credit movement* (`#1..#2`), *closing*; one row per account that has postings (list grows), totals, and a proof line (debits − credits = 0). In plain Excel = several pivots + hand-fixed totals each month; here one run.
**Files:** `scripts/ninja_template/MakeParityTB.java` → `legacy/parity_tb.xls` (Thai labels, POI so formulas are real) → `Xls2Xlsx` → `legacy/xlsx/parity_tb.xlsx`; witness `W37_TrialBalance.js`; gates `T_trialbalance` / `T_pdf_content` / `T_NEG_range` / `T_VACUOUS` in `run_all.sh`.
**Grammar learned (document in the manual):** (1) the first table of a statement must end in ` a` (alias) — it opens the statement; (2) `INNER JOIN …` goes in the TABLE column of a following row, the JOIN column holds extra conditions; (3) `AD_Client_ID` scoping is added automatically; (4) a **formula in the cell under each list column** marks where the list ends — the list grows into it; (5) a totals range must *include that spacer row* (`SUM(C6:C7)`): `SUM(C6:C6)` does NOT grow (refs above the insertion point don't move — POI `shiftRows` semantics, the same in the JS port). Hence the spacer row between list and totals.
**Measured (Dec 2006, real GardenWorld client postings):** 21 accounts, 131 cells judged vs an independent SQL aggregate, 0 mismatches; totalDebit = totalCredit = 4,258.90; opening and closing totals −0.00; negative control (a non-growing totals range) FAILS; a period with no postings prints INCONCLUSIVE. Full `run_all.sh`: 19 prior gates + 4 new, all as expected.
**Found by the PDF-content gate (not by eye):** (a) the renderer had no Thai font — 16 of 142 cells (all Thai labels) were absent from the PDF; fixed in `ninja_pdf.js` (Thai letters get their own font run, like Lao) + `W33` resolver (Noto Sans Thai, OFL); (b) long account names were cut by default column widths — fixed in the template (widths A12 B40 C–F16). After both: `§PDF_CONTENT cells=142 missingFromPdf=0`. The 98% PDF-geometry figure still applies only to the 3 reference fixtures — this template has no commercial-converter reference PDF.
**Open (step 1b):** the legacy-Java oracle for THIS fixture (and the formula-shifting edge cases: straddling ranges, absolute, cross-sheet, whole-column) needs the stopped Laos server (`~/idempiere-laos`) — ask before starting it. Company name is not in the twin snapshot (`ad_client` absent) so the heading shows only the period. Thai label source: standard English account-class terms translated by hand; verify wording with a Thai reader before the film.

## Measured results (fixtures over real GardenWorld rows; legacy plugin run on a local iDempiere clone as oracle)
- **Engine:** cells + log identical to the legacy plugin on all fixtures (e.g. 1,427 cells / 1,361 log lines on the row+column-insertion fixture); scale-blind executor fails as it should.
- **SQLite twin:** the PG-dialect statements run; `NUMERIC` scale is reproduced from dictionary side tables so the legacy `[0.00] ⇒ "returns nothing"` rule behaves identically (Java sees `BigDecimal` scale, SQLite REAL does not — closed with the twin's own `bigdecimal.js`).
- **Formatting:** `.xls`→`.xlsx` template migration (`Xls2Xlsx.java`, POI) keeps fonts/fills/borders/formats/merges/widths/heights; twin output vs the legacy output: 50,600 cells, 0 style differences (two-way). Library quirks caught and gated: ExcelJS stamps the merge-master style onto merged cells, leaves stale cell styles after row removal, rewrites the default font.
- **PDF (own renderer) vs the commercial converter's output (reference geometry goldens):** page = (36 + Σcol + 36) × (72 + Σrow + 72) pt (one page, not A4); row px = floor(pt·96/72); text inset 2 pt; thin border = hairline, medium 2 pt, double = two 1.334 pt lines + white gap. Small fixtures PASS; the 200×204 fixture matches page size, fills and 1,134/1,134 words; **known deviation D2, pinned (21+4 of 622 edge runs: the reference omits some shared vertical borders; the "neighbour decides" hypothesis was tested and rejected)**.
- **PDF content without a reference:** every visible cell's text must appear in the extracted PDF text (caught a real bug: a Lao-script font without ASCII punctuation silently dropped `/ . ( ) •` → per-run font fallback).
