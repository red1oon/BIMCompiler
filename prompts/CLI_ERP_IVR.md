## A. Binding owner decisions (do not re-litigate; quotes are the owner's)
- **Why (2026-11-11):** *"essentially like going back to my COBOL and MSDOS days … a CLI based ERP"*; users: clerks doing fast keyboard entry, and developers wanting an honest backdoor (every action still a journalled door line). - **One engine, one grammar.** Every screen/word compiles to door lines and PRINTS each before it runs (`→ line`); a person, a script, an AI and JS calling `door.runLine` read the same grammar (the single-source DSL). No second engine (AD-LAYER LAW 5).
- **MIS is the base, ERP gives way (2026-11-11).** `mis.*` for any AD table, document or not: `find list read describe sum group new update delete load add_window column pack menu`. `erp.*` keeps only document life: `actions complete void close reverse` (+ `find`, a document finder). - **Chips are the engine's, not a fixed set** (2026-11-11: *"UDC on the right as colored codes … ><> and enter"*): master row `[U Edit] [D Delete] [C Copy]`; a document's chips come from `erp.actions` (a completed order: no Delete). Delete asks y/N and only for a master or draft; refused for `Processed='Y'` (the test is the Processed flag, not DocStatus: `GridTable.dataDelete` L2163-2231).
- **Hidden-mandatory:** a form asks a dry run first (`mis.new dry=Y`) and shows ONLY the columns the engine cannot fill; the rest sit behind `[More]`; after a save the note lists what the engine filled.
- **Browser gets the CLI too (§1b):** the screen logic is ONE pure state machine `(state, input) -> {state, effects:[door line], screen}` in `mis_core.js` — no `require`/`process`/`fs`/escape codes (witness P1) — with replaceable renderers (ANSI terminal, page `<pre>`, plain line mode). Local-first, zero dependencies (Node's own raw keys and ANSI).
