**1. The phone-axe mechanism — DECIDED: a gate inside the ONE page.** Flagged modules keep their place in the page, but their tags are written by a small gate that a phone skips.
- *Now:* `viewer/viewer.html` holds 264 static `<script src>` tags (lines 862–1318); a browser starts fetching every one before any code runs, so no script can stop a phone downloading them.
- *Ours:* a module flagged `"phone": false` in `viewer/modules.json` has no static tag. One block near the top of the page lists the flagged files as runs (`_DESK = [[run 0 …], [run 1 …]]`); at each run's old position a one-line `_desk(i)` writes that run's tags with `document.write` when `window._caps.phone` is false. Desktop: same files, same execution order, started early by `<link rel=preload>` that the block adds. Phone: the files are never requested.
- *Why this one:* only parser-inserted tags keep the exact execution order (a script added from JS does not hold back the static tags after it, and `loader.js:230-254` starts `initViewer` as soon as `main.js` defines it). Same-origin `document.write` from a sync inline script is not subject to Chrome's slow-network block (that targets cross-site scripts). **Rejected:** a second generated phone page (two pages, two precache lists, shared links split); `APP.lazy` rows for everything (changes desktop first use and needs a census of every desktop entry point per feature — it stays the route for on-demand code, not for "never on a phone").
- *What the generator must learn:* a new site kind `desk` (a tag the gate writes). A `desk` site keeps its module `load: "boot"`, counts in the order check at its run's position, and is owned/bumped like a tag. `scripts/gen_manifest.js` today knows `tag | asset | inline | lazy` (SITE schema) and `manifest_source.js:372-393` judges order from `tag` sites only — unchanged, the order check would go blind on every gated module.
- *The probe moves first:* `window._caps` is set in `viewer/config.js:14-19`, tag line 872 — AFTER seven photoreal tags (862–868). `config.js` has `deps: []`; its tag becomes the first tag of the page.
- *Boot weight:* `scripts/boot_weight.js` counts static `<script src>` tags, so after the gate its `eager_bytes` IS the phone number; it gains `desk_bytes` so desktop growth stays visible.
- *Not solved by the gate (WO-10):* the service worker still precaches the flagged files on a phone in the background (`viewer/sw.js:1346-1377`, install set). Measure before designing.
- *Census comes from the manifest, not from reading by hand:* a kept module whose `deps` names a flagged module blocks the flag; a kept module whose `uses` names one is a call that needs a guard; `main.js:15-16` names its setup functions, most of them BARE (`setupCpeRoomTitle`, …) — a bare name of a missing file throws ReferenceError and stops boot.
