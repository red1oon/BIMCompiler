## 12. TEMPLATE-MATCHER STRATEGY (owner, 2026-11-03: "a template matcher strategy which I always propose from those early days … a certain set of info must be present. The unclear ones can be yellow marked")
Owner also states: the room names / dimensions / areas ARE on the sheet (drawn, not in the text layer). §11's doubt was about my cluster, not about their existence.
**Method:** the type (§7) supplies the set of things that MUST be present; the recogniser only tries to FIND those (match-against-expected), never to read freely. Outcome per expected item: **GREEN** (matched, count/identity agree), **YELLOW** (found but unclear, or count/identity disagree, or expected-but-absent, or present-but-unexpected), never silently dropped, never invented. Yellow reuses the DXF2BIM yellow-list/amber-editable convention (`~/bim-ootb/prompts/FILM_DXF2BIM_YELLOW_MARKINGS.md`) so the user resolves it in the existing UI; a resolved yellow becomes a stored template of the type (teach once, reuse).
**Step 0 DONE (text-layer tokens): `scripts/pdf2bim/type_checklist.py`, log `checklist.log`.** Expected set = the PDF's own p8 schedule (exact); found set = tags on p1 with the legend column removed (column of >=4 vocabulary words sharing x±3 pt — derived, not hard-coded):

|---|---|---|---|
| D1 / D2 / D3 | 2 / 3 / 2 | 2 / 3 / 2 | GREEN x3 — doors 7 = 7 |
| W1 / W2 | 1 / 4 | 1 / 4 | GREEN x2 |

Windows: schedule 7, plan 9 (the W3 excess is the whole difference). W-P6 therefore reports GREEN on doors, YELLOW on windows — an honest result the earlier OCR could not produce.
**Step 1 (next, not built): same match-against-expected for the DRAWN strings.** Expected list from the type vocabulary (Malay room names, `m²`, dimension values) + measured geometry (§9: wall-pair centre distances predict the dimension values). Candidate regions come from the stroked small-path clusters (§10/§11, symbols excluded by a shape test); matching = normalised ink-bitmap template distance; a candidate that beats a margin against exactly one expected item is GREEN, a close call or no match is YELLOW. Templates are seeded where truth is certain (known title-block strings, geometry-predicted dimensions confirmed across >=3 instances, then user-taught yellows) — never from a free-reading recogniser.
