Abstract

In one paragraph

Abu Dhabi already asks for an IFC model and a clash report with every infrastructure submission, but the technical review still runs on proprietary native files, and the guideline cites the 2018 IFC schema, which came before the 2024 standard that added roads and bridges. We propose an open, in-browser method that checks infrastructure IFC deliverables against IFC 4.3, compiles them into schedule, quantity and clash evidence, and keeps the data on the owner's machine, in line with the emirate's sovereign-data goal. Objectives

Three questions, in order

  1. 1
    Gap study
    Map the guideline's requirements [1] onto IFC 4.3 [7]: what is required, what IFC 4.3 now carries natively (alignment, stations, piles, earthworks, kerbs), and what is still missing.
  2. 2
    Open review method
    Check infrastructure IFC deliverables in the browser, on the reviewer's own machine. Report coverage and well-formedness separately, never as one pass/fail.
  3. 3
    From deliverable to evidence
    Compile the same IFC into 4D sequence, 5D quantities and clash results, and measure how much IFC 4.3 replaces inference from poor data with direct reading.

Limits, stated up front

What is not yet shown

Not yet tested
No IFC 4.3 infrastructure file has been run through the pipeline. Getting one is the first task for Papers 2 and 3.
Version
The guideline cited is v1.0 (Oct 2020). A newer DMT version may exist; check before Paper 1 calls it current.
One machine
Performance is measured on one laptop. Mobile per-tab memory limits are unverified.
Claims
No "first" or "only". A systematic prior-art search comes before any novelty sentence.
