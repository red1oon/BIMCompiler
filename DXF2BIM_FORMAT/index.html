    DXF2BIM format contract¶

    Generated by modeller/tools/gen_format_doc.js from the code's own tables: do not edit by hand. A person or another tool can read and write these files without reading our code.

    1. Versions and the compatibility rule¶

    Format Version Where it is stated
    run outputs (verdict.json, ops.json, bill.json, format.json) dxf2bim-run/1 the format field of each object file; bodies.json is a bare array (existing consumers read it as one) and is described by format.json
    settings sheet (the DXF2BIM-MARK layer) dxf2bim-marks/1 implicit: no version mark is written yet; a sheet without one is version 1 (the stamp needs an audit of BIMCompiler's golden outputs first)
    IFC output IFC4 FILE_SCHEMA; evidence in the property set Dxf2Bim_Evidence (older files: Pset_Dxf2Bim, still read)
    database the extractor's tables element_dxf2bim(guid, name, value) holds the evidence rows; absent when the IFC carries no evidence set

    Rule. A reader accepts every older version. A writer states the version it writes. Removing or renaming a key, a file or a code needs a version bump and a migration note here. Adding an optional key does not.

    2. The settings sheet: marks¶

    Plain text on layer DXF2BIM-MARK of an ordinary DXF, one @KEY=value per TEXT/MTEXT; a trailing @BY=model|user says who stated it. Unknown keys are reported (MARK:unknown_key), never ignored.

    Key Count Grammar Meaning
    @SET one per sheet name the set (building) name: every sheet of one set carries the same
    @VIEW one per sheet PLAN\|ELEV\|ROOF\|SECTION what the sheet is
    @NAME one per sheet text the sheet name
    @UNITS one per sheet mm\|cm\|m\|in\|ft the drawing units: confirmed by a person, the file header is only suggested
    @LEVEL one per sheet number (m) the storey level of a plan or roof sheet
    @FACE one per sheet minX\|maxX\|minY\|maxY which face of the building an elevation looks at
    @HAXIS one per sheet +X\|-X\|+Y\|-Y the elevation's horizontal axis in plan
    @REGION one per sheet x0,y0,x1,y1 the part of a sheet that is one storey / wing
    @ROOF one per sheet number (m) the roof top height of a roof sheet (no drawing states it)
    @CUT one per sheet X\|Y,<plan coordinate> where a section sheet cuts the plan
    @SCOPE one per sheet KEY \| name,x0,y0,x1,y1 a storey's annotation sheet, or a wing / zone of a sheet
    @FRAME one per sheet deg,x,y a wing drawn rotated by -deg about (x,y): the importer turns it back
    @GRIDX several letter at a position a plan grid line in X (the mark's own position is the line)
    @GRIDY several letter at a position a plan grid line in Y
    @GRIDH several letter at a position an elevation grid line (horizontal position)
    @Z several number (m) at a position a height datum: the z of the line the mark sits on
    @EXCLUDE several x0,y0,x1,y1 an area the reader skips (counted, never silent)
    @OPENING several door\|window,h0,y0,h1,y1 a stated opening rectangle on an elevation
    @LABEL several class,x,y[,z=m],text a drawing label bound to a class (type name / size)
    @SCHEDULE several text,door\|window,w,h \| text,wall,t one stated schedule row
    @TAG several class[,z=m],... a tag naming a drawn element's type
    @ALLOWANCE several door\|window,w,h a stated opening size where the drawing shows none
    @WALLTOP several number (m) \| handle:<h>,<m> a stated wall-top convention (never a default)
    @LAYER several layer,type what a layer means (the person's typing: a layer NAME is not evidence); types per view below
    @BODYZ several kind,z0,z1 the height range of a body kind that no elevation draws
    @SIZE several body id,x\|y\|w\|d,metres a stated size of one side of one body
    @DEFAULT several key,value a stated value for a registry setting (beats the editor's choice and the registry)

    Layer types per view (@LAYER=<layer>,<type>): PLAN: wall, wallline, slab, component, opening, glazing, ignore; ELEV: elevwall, elevdoor, glazing, levelline, ignore; ROOF: roof, glazing, ignore; SECTION: sectslab, sectwall, roof, ignore; ANY: dims, grid; BODY: column, beam, footing, gradebeam, member, plate, panel, bar, fan, net, doorswing.

    Units: mm = 0.001 m, cm = 0.01 m, m = 1 m, in = 0.0254 m, ft = 0.3048 m.

    4. Run outputs¶

    JSON Schemas (draft-07) in modeller/schemas/: dxf2bim-verdict.schema.json, dxf2bim-bodies.schema.json, dxf2bim-ops.schema.json, dxf2bim-bill.schema.json; W-FORMAT validates real outputs against them.

    Evidence tiers on every body (prov): drawn (measured from a drawn entity), derived (computed from drawn evidence plus a stated convention), assumed (no drawn evidence for its existence or position). Evidence properties on every body (set Dxf2Bim_Evidence): Provenance, SourceSheet, SourceHandle, SourceLayer, Kind, SizeBasis; from a details sheet also Note_<key> + NoteSource_<key> and Sched_<Kind>_<header> + SchedSource_<kind> + SchedBasis_<kind>.

    Layer ledger (verdict.layer_ledger, dxf2ledger.js): for every layer of every sheet, the entities on it, how it was typed, how many source entities produced a body, and a status: settings, annotation, ignored_by_choice, used, partly_used, evidence, typed_no_output, unread. unread = geometry on a layer nobody typed; typed_no_output = typed with a body kind but nothing was built; partly_used = some of its entities produced a body (the ratio is in used_entities / geometry); evidence = an elevation or section layer that gave heights or profiles. The entity account (§ACCOUNT) only says the DXF parser read every entity; the ledger says what was USED.
